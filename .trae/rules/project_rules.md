# 项目全局规则：英文术语中文解析

## 适用范围

本项目所有由 AI 生成或修改的内容，包括：

- 对话回复与说明
- Markdown 文档（docs/、openspec/、README）
- 代码注释
- Git commit message

## 规则

1. **首次出现必须标注**：英文技术名词在首次出现时，紧跟中文解析，格式为 `English(中文)`，英文与括号之间不留空格。
   - 正例：`openspec(规格驱动开发框架)`、`raycaster(射线拾取)`、`useFrame(逐帧钩子)`
   - 反例：`openspec（规格驱动开发框架）`（全角括号）、`openspec (规格驱动开发框架)`（多余空格）、`openspec`（无解析）
2. **同一章节只标一次**：同一文档、同一段落内重复出现时不再重复标注，避免噪音。
3. **不污染代码**：函数名、变量名、类型名、命令、路径、API 名称不标注；标注只出现在散文、注释和文档正文中。
4. **专有名词也标注**：产品名与库名首次出现同样需要解析，例如 `Three.js(Web 3D 渲染库)`、`zustand(轻量状态管理库)`。
5. **中文优先**：能用中文准确表达的概念直接用中文，不为了标注而硬塞英文。

## 示例

```markdown
项目使用 OpenSpec(规格驱动开发框架) 管理变更：
每次改动先生成 proposal(提案)，再按 tasks(任务清单) 实施，
最后由 verify(验证) 环节确认实现与 spec(规格) 对齐。
```
