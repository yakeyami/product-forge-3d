## 2. 各层技术对比

### 2.1 渲染引擎层

| 方案 | 定位 | 生态 | 上手成本 | 适合本项目 |
|---|---|---|---|---|
| **Three.js** ⭐ | 轻量渲染库 | ★★★★★ | 中 | ✅ |
| Babylon.js | 完整游戏引擎 | ★★★★ | 中高 | ⚠️ 偏重 |
| PlayCanvas | 游戏引擎 + 编辑器 | ★★★ | 中 | ❌ |
| A-Frame | 声明式 VR 框架 | ★★ | 低 | ❌ 太窄 |
| `<model-viewer>` | Web Component 封装 | ★★ | 极低 | ❌ 学不到原理 |

**推荐 Three.js**：事实标准、大厂案例最多、粒度合适（能理解场景图/相机/光照/材质），且可深入到后处理与 WebGPU。

### 2.2 框架集成层

| 方案 | 适用 | 说明 |
|---|---|---|
| **React Three Fiber + drei** ⭐ | React | JSX 写 3D，声明式、组件化，大厂主流写法 |
| TresJS | Vue | Vue 版 R3F |
| 原生 Three.js | 任意 | 最底层，但与 UI 状态联动需手写胶水代码 |

**策略**：用半天时间读一遍原生 Three.js 最小示例建立心智模型，正式项目直接走 R3F。

### 2.3 内容管线层

| 技术点 | 说明 | 深度 |
|---|---|---|
| **glTF / GLB** ⭐ | 3D 界的"JPEG"，行业标准 | 必学 |
| 免费模型来源 | Khronos 示例、Sketchfab、Poly Pizza | 直接用 |
| Blender | 建模/改模 | 选修 |
| Draco / Meshopt | 模型压缩 | 延伸 |

**不做建模**，直接用现成 glTF 模型；学习重点是渲染与交互，不是美术。

### 2.4 辅助库层

| 库 | 用途 | 是否引入 |
|---|---|---|
| OrbitControls | 拖拽 / 缩放相机 | ✅ 必用 |
| drei | 环境光、阴影、加载进度等封装 | ✅ |
| lil-gui | 调参面板 | ✅ |
| stats.js | FPS 监控 | ✅ |
| postprocessing | 辉光 / 景深 | ⚠️ 选修 |

### 2.5 工程方法论层

| 工具 | 角色 |
|---|---|
| **OpenSpec** | 管"做什么"：explore → propose → apply → verify → archive，需求有文档、变更可追溯 |
| **Superpowers** | 管"怎么做"：brainstorming → writing-plans → TDD → code review → verification，防跑偏 |

组合：`想法 → OpenSpec 提案 → Superpowers 拆计划+TDD 实现 → OpenSpec 验证归档`
