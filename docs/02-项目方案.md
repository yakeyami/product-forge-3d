# Web 3D 学习项目 · 第二阶段：项目方案

> 状态：已定稿 | 项目代号：`product-forge-3d`

## 1. 项目定位

一个可交互的 3D 球鞋配置器：用户可 360° 查看商品、实时切换部件颜色与材质、切换相机视角并导出截图——对标天猫 3D 商品页 / 苹果产品页的简化版。

## 2. 技术栈

见 [01-技术选型.md](./01-技术选型.md) 第 3 节。

## 3. 功能范围

### 3.1 MVP（8 项，全部必做）

| # | 功能 | 说明 |
|---|---|---|
| F1 | 模型加载 | 加载 GLB，带进度条，失败有兜底 |
| F2 | 轨道交互 | 拖拽旋转、滚轮缩放、惯性阻尼、空闲自动旋转 |
| F3 | 环境光照 | 环境光 + 接触阴影，呈现 PBR 质感 |
| F4 | 换色 | 点击部件 → 换颜色 |
| F5 | 换材质 | 材质预设（哑光 / 金属 / 亮面） |
| F6 | 配置面板 | DOM 浮层：部件选择 + 色板 + 材质预设 |
| F7 | 相机视角 | 预设机位（正面 / 侧面 / 细节），平滑过渡 |
| F8 | 截图导出 | 保存当前视角 + 配置的 PNG |

### 3.2 延伸（MVP 完成后再评估）

- E1 后处理特效（辉光 / 景深）
- E2 Draco 压缩 + 性能面板
- E3 配置持久化（URL 分享）
- E4 移动端触摸适配

## 4. 要点

1. 场景图心智模型：Scene → Mesh → Geometry + Material
2. PBR 材质：color / metalness / roughness
3. IBL 环境光照：为什么商品图用环境光而不是硬打灯
4. glTF 结构：节点树 + 材质 + 贴图，按节点名找部件
5. 相机控制：阻尼、极角与距离限制
6. React ↔ 3D 状态桥接：状态走 store，逐帧逻辑走 useFrame

## 5. 难点

| # | 难点 | 应对 |
|---|---|---|
| D1 | 免费且部件分离的 GLB 难找 | 程序化占位球鞋兜底，知识点不减 |
| D2 | 同材质被多网格共享导致串色 | 按节点分组，必要时克隆材质 |
| D3 | React 重渲染与 60fps 渲染循环冲突 | 状态走 zustand，逐帧走 useFrame，禁止逐帧 setState |
| D4 | 真实感调教 | lil-gui 现场调参，学习色调映射与光照 |
| D5 | 贴图过大导致掉帧 | stats 监控，贴图限制 2K，延伸阶段压缩 |

## 6. 方法论落地

- **OpenSpec**：能力按功能域切分 —— `model-viewing`、`product-configuration`、`presentation`；每个里程碑一个 change，验收后 archive
- **Superpowers**：可单测的纯逻辑（状态、材质映射、截图工具）走红绿 TDD；3D 视觉用 spec 里的 Scenario 做人工验收（3D 渲染结果难以断言，不做伪 TDD）

## 7. 里程碑

| 里程碑 | 内容 | 产出 |
|---|---|---|
| M0 | 工程初始化 + OpenSpec / Superpowers 接入 | 可运行空项目 + 方法论文档 ✅ |
| M1 | 3D 心智速通（原生 Three.js 旋转立方体） | 单文件 demo |
| M2 | 模型加载 + 轨道控制 + 环境光照（F1-F3） | 商品可看可转 |
| M3 | 换色 + 换材质 + 面板（F4-F6） | 核心卖点完成 |
| M4 | 相机视角 + 截图 + 性能 + 部署（F7-F8） | 可分享的线上作品 |
