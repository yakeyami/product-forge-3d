# 架构总览

> 全局视角。单次变更的技术决策见 `openspec/changes/*/design.md`，需求约束见 `openspec/specs/`。

## 1. 分层

```
┌──────────────────────────────────────────────┐
│ UI 层（DOM）  App.tsx / 配置面板（M3）         │
│  品牌信息、操作提示、色板、材质按钮             │
├──────────────────────────────────────────────┤
│ 状态层  src/store/configurator.ts (zustand)   │
│  部件选择 / 颜色 / 材质预设 —— DOM 与 3D 的桥 │
├──────────────────────────────────────────────┤
│ 场景层（R3F） src/components/                 │
│  Scene → StudioEnvironment / SneakerModel     │
├──────────────────────────────────────────────┤
│ 资源层  src/three/config.ts + public/models   │
│  路径统一拼 BASE_URL，模型按包围盒归一化       │
└──────────────────────────────────────────────┘
```

UI 层与场景层**不直接互相引用**，只通过 store 通信。这样换色面板改版不会牵动 3D 代码，反之亦然。

## 2. 运行时数据流

```
用户点击色板（DOM）
   → zustand.setPartColor('upper', '#f00')
   → SneakerModel 订阅 colors，useMemo 生成材质参数
   → three 材质更新（下一帧渲染生效）
```

反向（拾取方向，M3 才做）：

```
raycaster 命中 mesh → 节点名映射为 PartId → store.setActivePart
```

约束：**逐帧变化的量（相机、旋转）走 `useFrame` / controls，不进 React state**；只有用户意图（选中部件、颜色）才进 store。这是 D3 难点（React 重渲染 vs 60fps 循环）的实现边界。

## 3. 目录职责

| 路径 | 职责 | 不该放什么 |
|---|---|---|
| `src/App.tsx` | 页面布局、品牌区、操作提示 | 3D 对象、材质逻辑 |
| `src/components/Scene.tsx` | Canvas、相机、控制器、自动旋转计时器 | 具体模型外观 |
| `src/components/StudioEnvironment.tsx` | 环境光、展示台、接触阴影 | 商品模型 |
| `src/components/SneakerModel.tsx` | 模型加载、归一化、失败降级、占位模型 | 页面文案、UI 状态 |
| `src/store/configurator.ts` | 部件/颜色/材质契约与操作 | three 对象引用 |
| `src/three/config.ts` | 资产路径、归一化尺度、展示台参数 | 组件 |
| `openspec/specs/` | 已归档的行为规格（事实源） | 实现细节 |
| `openspec/changes/` | 在途变更的提案、规格、设计、任务 | 已归档内容 |

## 4. 关键设计决策（摘要）

| 决策 | 结论 | 详见 |
|---|---|---|
| 3D 写法 | R3F 声明式组件树，而非命令式 `scene.add` | `add-model-viewing/design.md` D1 |
| 相机 | drei `<OrbitControls>` + 自管 3 秒空闲计时 | D2 |
| 光照 | Lightformer 自建演播室环境，不依赖 CDN HDR | D3 |
| 模型加载 | `useGLTF` + Suspense 进度 + ErrorBoundary 降级 | D4 |
| 状态 | zustand，本次只建契约不接 UI | D5 |
| 性能 | `dpr={[1,2]}`、贴图 ≤2K、接触阴影替代 shadow map | D6 |

## 5. 扩展点

| 里程碑 | 落点 | 说明 |
|---|---|---|
| M3 换色/换材质 | `SneakerModel` 材质绑定 + `App` 侧面板 | 部件名 → 节点分组映射放 `src/three/parts.ts`；共享材质需克隆后再改 |
| M3 点击拾取 | `Scene` 内 `onPointerDown` + raycaster | 向上回溯到带 `userData.part` 的父节点 |
| M4 相机预设 | `Scene` 暴露 controls 引用 | 用 `lerp`/`useFrame` 平滑过渡，不改 store |
| M4 截图 | 新增 `src/three/snapshot.ts` | `gl.render` 后 `toDataURL`，注意 `preserveDrawingBuffer` |
| 延伸 后处理 | `Scene` 外包 `<EffectComposer>` | 先做性能预算，再上特效 |

## 6. 硬约束

1. 所有静态资源路径必须拼 `import.meta.env.BASE_URL`，否则 GitHub Pages 子路径 404。
2. `vite.config.ts` 的 `base` 必须与仓库名一致。
3. 不使用依赖外部 CDN 的运行时资源（HDR、字体、贴图）。
4. 品牌与模型素材必须可商用，不使用 Nike / Adidas 等商标。
5. 开发期调试组件（`<Stats />`）只在 `import.meta.env.DEV` 下挂载。

## 7. 性能预算

| 指标 | 目标 |
|---|---|
| 桌面 Chrome 帧率 | ≥ 50 FPS |
| 首屏 JS | 当前约 1.3MB（three 占大头），后续按需拆包 |
| 模型文件 | ≤ 5MB，延伸阶段做 Draco / Meshopt |
| 贴图 | 单张 ≤ 2K，总显存 ≤ 64MB |
